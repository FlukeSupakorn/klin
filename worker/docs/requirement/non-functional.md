# Non-functional Requirements (ความต้องการเชิงคุณภาพ)

### NFR-01 ด้านประสิทธิภาพ (Performance)

- ระบบต้องสามารถสร้างหน้า Preview สำหรับอย่างน้อย 20 ไฟล์ภายในเวลาไม่เกิน 30 วินาทีบนเครื่องทดสอบตามสเปกที่กำหนดใน Test Bed
- ระบบต้องสามารถสแกนหาไฟล์ซ้ำในโฟลเดอร์ที่มีไฟล์อย่างน้อย 1,000 ไฟล์โดยไม่ทำให้แอปพลิเคชันค้างหรือปิดตัวเอง
- ระบบต้องออกแบบให้รองรับการจัดการไฟล์จำนวนมาก (หลักหลายพันไฟล์) โดยไม่ทำให้การตอบสนองของ UI ช้าลงอย่างมีนัยสำคัญ

---

### NFR-02 ด้านความน่าเชื่อถือ (Reliability)

- หากการเรียกใช้งาน AI ล้มเหลว ระบบต้องไม่ทำการย้ายหรือลบไฟล์ และจะแสดงข้อความผิดพลาดให้ผู้ใช้ทราบ
- ระบบต้องสามารถกลับมาทำงานต่อจากสถานะล่าสุดได้ หลังจากเกิดเหตุฉุกเฉิน เช่น โปรแกรมปิดเองหรือเครื่องดับ โดยไม่ทำให้ข้อมูลประวัติการจัดการไฟล์สูญหาย
- ระบบต้องมีการจัดเก็บ Log ของข้อผิดพลาดและเหตุการณ์สำคัญสำหรับใช้ในการดีบัก

---

### NFR-03 ด้านความปลอดภัยและความเป็นส่วนตัว (Security & Privacy)

- โดยค่าเริ่มต้น ระบบต้องประมวลผลไฟล์ทั้งหมดแบบ local บนเครื่องผู้ใช้ และต้องไม่ส่งเนื้อหาไฟล์ออกสู่ภายนอกโดยไม่ได้รับความยินยอม
- ~~ในกรณีที่ผู้ใช้เลือกใช้โมเดล AI บน Cloud ระบบต้องส่งข้อมูลผ่านช่องทางที่เข้ารหัส (เช่น HTTPS/TLS) เท่านั้น~~
- ระบบต้องไม่เก็บเนื้อหาของไฟล์ทั้งฉบับใน Log หรือฐานข้อมูล ยกเว้นข้อมูลที่จำเป็น เช่น ชื่อไฟล์ เส้นทางไฟล์ และผลการจัดหมวดหมู่
- ระบบต้องรองรับการป้องกันการลบไฟล์โดยไม่ตั้งใจ เช่น การถามยืนยันก่อนลบไฟล์จริง หรือย้ายไปโฟลเดอร์ถังขยะแทนการลบถาวร

---

### NFR-04 ด้านการใช้งาน (Usability)

- UI ต้องรองรับผู้ใช้ทั่วไปที่ไม่ใช่นักพัฒนา โดยใช้คำอธิบายฟีเจอร์เป็นภาษาไทยหรือภาษาอังกฤษที่เข้าใจง่าย
- การทำงานหลักสำหรับ "จัดการไฟล์" ต้องไม่เกิน 3 ขั้นตอนหลัก: เลือกโฟลเดอร์ → ตรวจสอบ Preview → ยืนยันการจัดการไฟล์
- ระบบต้องมีข้อความแนะนำ (tooltip / helper text) ในหน้าตั้งค่า Watcher, Destination และ Template Mapping

---

### NFR-05 ด้านความเข้ากันได้ (Compatibility)

- ระบบต้องสามารถทำงานได้บน Windows 10 และ Windows 11 แบบ 64-bit ตามสเปก Test Bed ที่ระบุ
- ระบบต้องพัฒนาโดยใช้ Tauri + React + TypeScript ในส่วนของ UI และ Rust/Python สำหรับส่วนประมวลผล เพื่อให้สอดคล้องกับเทคโนโลยีที่ศึกษาไว้

---

### NFR-06 ด้านการบำรุงรักษาและการขยายระบบ (Maintainability & Extensibility)

- โครงสร้างซอร์สโค้ดต้องแยกส่วน Frontend, Desktop Shell (Tauri), Backend Worker และโมดูล AI ออกจากกันอย่างชัดเจน เพื่อง่ายต่อการปรับปรุง
- การเพิ่มประเภทไฟล์ใหม่หรือโมเดล AI ใหม่ต้องสามารถทำได้โดยการเพิ่มโมดูล/คอนฟิกเพิ่มเติม โดยไม่ต้องแก้โค้ดส่วน UI หลักจำนวนมาก
- ต้องมีเอกสารประกอบโค้ดและคู่มือการติดตั้ง/ใช้งานสำหรับนักพัฒนาและผู้ใช้

---

### NFR-07 ด้าน Localization และการตั้งค่า

- ระบบต้องรองรับอย่างน้อย 1 ภาษาเต็ม (ไทยหรืออังกฤษ) และออกแบบโครงสร้างให้สามารถเพิ่มภาษาอื่นได้ในอนาคต
- การตั้งค่าทั้งหมดของผู้ใช้ (เช่น Watcher Folder, Template, ภาษา, ธีม) ต้องถูกบันทึกไว้และโหลดกลับมาโดยอัตโนมัติเมื่อเปิดโปรแกรมใหม่

---
